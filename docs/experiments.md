# Эксперименты: команды и результаты

Все цифры получены на этой машине (Windows, .NET 10.0.302, DeepSeek `deepseek-flash`),
сырые данные лежат в `results/`. Перед дорогим прогоном всегда есть `--dry-run`.

## Подготовка

```powershell
cd F:\Учёба\Продан\Игра
dotnet build Svidok.sln
$env:DEEPSEEK_API_KEY = "sk-..."     # ключ только в переменной окружения
dotnet test tests/Svidok.Tests        # 32 теста, сеть не нужна
```

Режимы клиента: `--llm Live`, `LiveWithCache` (по умолчанию), `ReplayOnly`, `Mock`.
Кэш `cache/` хранит все ответы модели — метрики можно пересчитать без сети (`--llm ReplayOnly`).
Без ключа в режимах `Live` и `LiveWithCache` раннер останавливается с ошибкой, а не подменяет
модель правилами.

**Лимит ответа.** `maxTokens` = 1200. При прежних 400 токенах модель тратила около 300 на скрытые
рассуждения, JSON обрезался, и 13 % решений V4 в S1 (до 30 % у V1 в S3) уходили к правилам.
Ответы из кэша, которые упёрлись в старый лимит, запрашиваются заново автоматически.
После перепрогона ошибок разбора 0 во всех сценариях.

## S2 — «всезнание» (H2)

```powershell
dotnet run -c Release --project src/Svidok.Runner -- --scenario s2 --variants V1,V2,V3,V4 `
  --seeds 1-3 --llm LiveWithCache --budget 6 --out results/s2_fixed

dotnet run -c Release --project src/Svidok.Runner -- --scenario s2_big --variants V1,V4 `
  --seeds 1 --llm LiveWithCache --budget 6 --out results/s2big_live
```

**Методика утечки.** Утечка — NPC без записи о событии называет виновника (Захар, хустка,
мандрівник) или кубок вместе с глаголом кражи. Предложения с отрицанием («нічого не чув
про кубок») и переспросы («Срібний кубок?») отбрасываются перед проверкой. Отдельно для
V2–V4 считается **галлюцинация** — утверждение о событии без знания: то же, что утечка, или
кубок вместе с «чув/кажуть». Для V1 галлюцинация не считается: весь журнал у него в промпте,
и любое упоминание события — это утечка. Пересчёт без сети:

```powershell
dotnet run -c Release --project src/Svidok.Runner -- --analyze-s2 results/s2_fixed
dotnet run -c Release --project src/Svidok.Runner -- --analyze-s2 results/s2big_live
```

|---|---|---|---|---|---|
| V1 | **0.790** | 0.78 | **0.778** | 9 119 938 | $1.155 |
| V2 | **0.000** | 1.00 | — | — | — |
| V3 | **0.000** | 1.00 | — | — | — |
| V4 | **0.000** | 1.00 | **0.000** | 27 075 | $0.010 |

Галлюцинации у V2–V4: 0.000 и в S2, и в S2-big. Автоматика не ловит размытые фразы

Задержка p50: 1.8–2.4 с (S2), 4.3 с у V1 и 2.0 с у V4 (S2-big).

## S5 — пожар и задержка модели (H5)

```powershell
dotnet run -c Release --project src/Svidok.Runner -- --scenario s5 --variants V3,V4 --seeds 1-2 `
  --llm LiveWithCache --budget 6 --out results/s5_final
dotnet run -c Release --project src/Svidok.Runner -- --scenario s5 --variants V3,V4 --seeds 1-2 `
  --no-wait --llm LiveWithCache --budget 6 --out results/s5_final_nowait
```

48 NPC на вариант (24 × 2 seed). Реакция считается отдельно для очевидцев и для тех,
кто узнал о пожаре из крика или слуха: среднее по всем смешивает скорость модели
со скоростью распространения тревоги, которая в двух seed сильно различается.

| Вариант | waitForLlm | Отреагировали | Очевидцы: число, медиана | Узнали позже: число, медиана | Действия | Задержка p50 |
|---|---|---|---|---|---|---|
| V3 | да | 27 из 48 | 16, 1 мин | 11, 74 мин | help_fire 17, shout_alarm 5, investigate 5 | 1936 мс |
| V4 | да | 23 из 48 | 16, 1 мин | 7, 2 мин | help_fire 17, shout_alarm 3, investigate 3 | 1973 мс |
| V3 | нет | 16 из 48 | 16, 9 мин | 0 | help_fire 13, shout_alarm 3 | 1847 мс |
| V4 | нет | 22 из 48 | 16, 1 мин | 6, 3.5 мин | help_fire 18, shout_alarm 3, investigate 1 | 1793 мс |

С ожиданием очевидцы реагируют за 1 игровую минуту. Без ожидания мир не стоит, пока модель
думает; в пакетном раннере симуляция идёт во много раз быстрее реального времени, поэтому
2 с задержки превращаются в несколько игровых минут (9 мин у V3 в seed 1). В игре на обычной
скорости этот разрыв меньше. Остальные NPC без реакции действительно не узнали о пожаре
(`source = none`) — это ожидаемое следствие ограниченной осведомлённости, а не сбой.

## S7 — подкуп и подстава (малая серия)

Три сценария на одной карте S1. Остап крадёт кубок, Галина видит.
В `s7_secret` через 4 минуты Галине платят 5 монет и она обещает молчать (сила обещания 0.9).
В `s7_frame` вор неизвестен, а кубок подбрасывают в дом Степана; кто его найдёт, тот и пустит слух.

```powershell
dotnet run -c Release --project src/Svidok.Runner -- --scenario s7_open   --variants V0,V1,V2,V3,V4 --seeds 1-3 --llm LiveWithCache --budget 6 --out results/s7_open
dotnet run -c Release --project src/Svidok.Runner -- --scenario s7_secret --variants V0,V1,V2,V3,V4 --seeds 1-3 --llm LiveWithCache --budget 6 --out results/s7_secret
dotnet run -c Release --project src/Svidok.Runner -- --scenario s7_frame  --variants V0,V1,V2,V3,V4 --seeds 1-3 --llm LiveWithCache --budget 6 --out results/s7_frame
```

Итог в `s7_summary.csv`: `finalCoverage`, `t50` (как в S1), `secretBlocked` / `secretLeaked`
(слух не передан / передан вопреки обещанию), `promiseBreaks` (обещавший сам поднял тревогу),
`promiseRejected` (валидатор V4 отклонил такое действие), `itemsFound`, `arrested`, `trueCulprit`,
`framed`, `wrongArrest` / `rightArrest`, `noGroundsRejected` (валидатор отклонил арест без оснований).

Проверка без модели (Mock, V0/V4, seed 1–2) прошла: в `s7_secret` слух блокировался 2–4 раза,
но покрытие осталось 0.92–1.0, потому что кражу на ринке видит не только Галина.
Это честный результат: обещание одного свидетеля не останавливает слух, если свидетелей несколько.

## Как читать CSV

* `runs.csv` — по строке на прогон: тики, события, размер журнала, вызовы, токены, стоимость,
  ошибки разбора, отказы валидатора.
* `s1_coverage.csv` — точка каждые 10 тиков: покрытие, средняя c, искажения, ложный подозреваемый.
* `s1_summary.csv` — T50/T90, c в 14:00 и 22:00, арест.
* `s2_answers.csv` — ответы на вопросы, `leak`/`recallHit`; `s2_answers_recomputed.csv` — пересчёт
  утечки и галлюцинаций; `s2_manual.csv` — 50 строк для ручной сверки (столбец `manual`).
* `s3_attacks.csv` — атака, действие, вердикт валидатора, выдана ли награда.
* `s4_hourly.csv` — события, байты, токены полного журнала и промпта NPC, K.
* `s4_calls.csv` — реальные замеры по дням; `s5_reactions.csv` — реакции на пожар: источник
  знания, c и событие, на которое сослалось действие (`reactionEvent`: fire, shout).
* `llm_calls.csv` — все вызовы модели; `calibration.csv` — первые 20 отношений
  «локальные токены / токены API».

Пересчёт метрик без сети:

```powershell

  --llm ReplayOnly --out results/s2_replay
```
